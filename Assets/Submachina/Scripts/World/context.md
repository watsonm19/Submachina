# World Systems

Procedural world generation and the world entities the submarine interacts with (rocks, mining resources, O2 bubbles, enemies). World objects never hold a submarine reference — they resolve the sub from context (`Submarine.FindNearest`, `GetComponentInParent<Submarine>`, or a reference injected at spawn). See `../Submarine/context.md` for the facade these objects target.

## Generation

Spawning is **data-driven**: WHAT spawns lives in `SpawnProfile`/`SpawnRule` assets, not in code. `ChunkSpawner` owns the grid/camera/persistence; `WorldChunk` is a generic executor. See `Spawning/` for the rule types.

- **ChunkSpawner** — generates the world as a persistent grid of chunks around the camera. Pre-spawns every cell within `spawnRadius` (e.g. a 7×7 ring) and **never despawns** them. Maps grid coords → world space with `FloorToInt` (correct for negative Y), filters out cells above the surface (Y ≥ 0), and instantiates one `WorldChunk` per cell, handing it the assigned `SpawnProfile` and a **deterministic per-cell seed** (`SeedMode` = coord-hash, optionally mixed with `worldSeed`). Keyed dictionary keeps chunks unique. Depends on `Camera.main`. A scene gizmo draws each rule's active depth band.
- **WorldChunk** — `Initialize(topY, height, halfWidth, worldX, depth, profile, seed)` builds a seeded `System.Random` + a `SpawnContext` and runs every rule in `profile.AllRules` against the chunk's depth. Holds no rock/enemy/resource knowledge. Fires `onChunkGenerated` (UnityEvent). Spawned entities are parented under the chunk and resolve their own sub deps from context.
- **WorldBoundary** — attach to the camera. Creates invisible left/right `BoxCollider2D` walls parented to the camera so they scroll with the viewport. `halfWidth` must match `ChunkSpawner`'s cell half-width so the walls align with the generated world edges; `wallHeight` covers the view plus buffer.

## Spawning (data model — `Spawning/`)

- **SpawnProfile** (SO) — the rule set a level uses; referenced by `ChunkSpawner`. Aggregates reusable `SpawnRule` assets (`sharedRules`) **and** inline one-off rules (`inlineRules`) via `AllRules`. Has a `globalDensityMultiplier`, validation warnings, and editor buttons: **Test Spawn Chunk** (throwaway in-editor chunk at a depth) and **Generate Default Rules** (scaffolds the 7 legacy-parity rules via `SpawnProfileDefaults`).
- **SpawnRule** (SO) — thin reusable wrapper around one `SpawnRuleData`.
- **SpawnRuleData** — one spawnable: `prefab`, `DepthRange` (min + optional max), `prevalenceByDepth` curve, `CountModel`, `maxPerChunk`, `minSpacing`, `[SerializeReference] PlacementStrategy`, optional `[SerializeReference] InstanceConfigurator`, `zoneTag` + `developerNotes` (per-segment dev notes). `Execute(in ctx, rng, density, parent)` does depth-gate → count → place (spacing retries) → instantiate → scale/configure.
- **PlacementStrategy** (`[SerializeReference]`) — `ScatterPlacement` (width band + insets), `WallProtrusionPlacement` (flush-edge rocks; returns a `scaleOverride` = protrusion×height), `CenterBandPlacement` (tighter central band). Returns a `PlacementResult { position, scaleOverride? }`.
- **CountModel** — `SingleRoll` (probability), `Range` (flat min–max), `CurveRange` (ramps with depth). Optional `CountSplit` (Floor/Ceil half) lets two rules share one rounded budget — used to reproduce the original wall/center rock split exactly.
- **InstanceConfigurator** (`[SerializeReference]`) — post-spawn setup. `DepthSizeConfigurator` (depth-driven O2 `SetSize`), `DepthScaleConfigurator` (depth-driven rock localScale).
- **SizeSampler** — shared roll→curve→lerp helper, reused by `O2DropConfig` and `DepthSizeConfigurator`. **SpawnRng** — `System.Random` float/bool extensions for deterministic sampling.
- Generation is reproducible: same `worldSeed` + cell → identical chunk. `LevelConfig`'s zone spawn budgets (`ZoneConfig`) are **deprecated** by this system; its world shape, `ZoneType`, and `ExitGateWorldY` remain live (`ZoneType` is an optional inspector tag on rules, not a gate).

## Entities

- **EnemyController** — sea-creature AI: Patrol → Chase → WindUp → Attacking → AttackCooldown (+ terminal Dead) state machine. Acquires the player via `Submarine.FindNearest(transform.position)` in Start and caches its `Health`. Detection uses `detectionRadius`/`deaggroRadius` hysteresis; the attack telegraphs (orange tint + DOTween `DOPunchScale` on an intent indicator) then lunges (red, `lungeSpeed`), dealing `attackDamage` to the player's `Health` on contact (guarded to once per lunge). Subscribes to its own `Health.onDeath` to drop `o2BubblePrefab` ×`bubbleDropCount`. Composes with `HitFlash` (which preserves these state tints). Force-free Rigidbody2D driven by `linearVelocity`.
- **MiningResource** — laser-mineable node (on the "Resource" layer, trigger `CircleCollider2D`). `SetMiningProgress(0..1)` is called by `MiningLaser` each frame the beam holds it, lerping the sprite toward white. `Collect(Submarine sub, airMultiplier = 1)` — called by the laser at completion (separated so magnet/auto upgrades can also call it) — awards `sub.Resources.AddResources(...)` and rolls `scrapDropChance` for `sub.Scrap.AddScrap()`.
- **O2Pickup** — air bubble (enemy drop or passive scatter; trigger `CircleCollider2D`). `Collect(Submarine sub, airMultiplier = 1)` restores `sub.O2.RestoreCapacity(...)` and `sub.O2.AddAir(replenish × multiplier)`, fires `onCollected`, then self-destructs. `collectOnContact` is **off by default** — collection normally goes through `O2PickupPump`'s sweet-spot mechanic (which calls `Collect` with a graded multiplier); when on, `OnTriggerEnter2D` resolves the sub via `other.GetComponentInParent<Submarine>()`.
- **RockObstacle** — breakable rock (Collision layer). Broken by the `MiningLaser` (hold-beam timer → `Break()`) or by a fast enough collision on `breakFromLayers`. `SetProgress`/`ResetProgress` tint it toward `damagedColor` ("heating up") and back, caching each renderer's original color in `Awake` via `GetComponentsInChildren`.

## Rock / ore visuals

The minable rock reads as a clustered, lit ore patch (Delta-V / Factorio style).

- **Procedural art** — `TerrainObjectGenerator` (`World/Editor/`, menu **Submachina/Terrain Object Generator**; successor to the old `OreNuggetGenerator`) is an all-purpose rocky/crystally/dirty terrain-object sprite baker. Per variant it writes `{Name}_{i}_albedo.png` + `_normal.png` (+ optional `_mask.png` spec mask) into a chosen folder (default `Assets/Submachina/Art/Terrain/`), reproducible from `seed`. Split across three files: `TerrainObjectSettings` (serializable data + `TerrainObjectPreset` SO), `TerrainObjectBaker` (pure pixel-buffer generation, shared by preview and bake), `TerrainObjectGenerator` (Odin window + importer wiring). Features:
  - **Shapes** — silhouette families (`Blob`/`Boulder`/`Slab`/`Shard`/`Cluster`) built as signed fields: superellipse squareness, exact flat-edged polygons with corner rounding, smooth-min merged lobes; plus aspect stretch, per-variant rotation, rim wobble and domain warp. Height mass is shaped by `domeStrength` × `domeProfile` (plateau ↔ mound).
  - **Surface** — FBM surface noise, Worley cracks, rim AO, mineral specks (optionally shiny in the spec mask), optional sedimentary **strata** bands (angle/frequency/warp), and a `baseColor` (keep grey for runtime tinting).
  - **Paint layers** — an ordered list of noise-masked overlays (flat tint or an **external tiled PNG**, e.g. downloaded/AI-generated sand/dirt/rust), with `heightBias` to collect in crevices (sediment) or on ridges (dust), and optional bump influence on the normal.
  - **Crystals** — `Prisms` (tapered quartz-point bundles fanning out of the rim or anywhere) and/or `Druse` (amethyst-bed patches of Voronoi-cell terminations), rasterized as analytic height fields (baked 3D-ish relief), with own colour + variation, tip brightness, facet contrast, and a high `_SpecMask` value so they glint while rock stays dull. `separateCrystalLayer` bakes them as their own `_crystal_albedo/_normal` overlay sprite (stack on a child renderer) so the rock can be runtime-tinted without tinting the crystals.
  - **Presets** — `TerrainObjectPreset` assets (Save / Save As… / Load in the window, or Assets > Create > Submachina) snapshot the full settings for recall and tweaking.
  - **Preview** — in-window Albedo / Normal / Lit panes (Lit simulates torch direction + scene tint + spec mask), auto-refreshing (debounced) as settings change, capped at 256px for speed.
- **Per-sprite normals** — each normal is attached as the albedo sprite's `_NormalMap` **Secondary Texture**, so all nuggets share the one default `Sprite-Lit-Default` material (no per-nugget material instances). Normals are imported as **Default, sRGB off, uncompressed** because the URP 2D sprite normals pass reads straight RGB (`UnpackNormalRGBNoScale`) — *not* Unity's NormalMap type.
- **Grayscale + tint** — textures are neutral grey so `OreSpecular.prefab`'s `SpriteRenderer.color` tint drives the look (and the heat lerp), and one texture set can serve copper/scrap via different tints.
- **Shadows** — each nugget carries a silhouette `ShadowCaster2D` (cloned from the prefab's original). At scale (hundreds of rocks) this multiplies casters and the 2D renderer is capped at 1 shadow texture — if shadows get heavy, keep casters only on the 1–2 largest nuggets.
- **Metallic shine** — URP 2D lighting is diffuse-only (no specular), so the nuggets use a custom material `Materials/OreLit.mat` (shader `Shaders/SpriteLitSpecular.shader`, `Submachina/2D/SpriteLitSpecular` — a **generic** sprite specular shader, not ore-specific). It's a verbatim copy of URP's Sprite-Lit-Default with one addition in the Universal2D pass: a Blinn-Phong **HDR specular** computed from a surface normal — either the sprite's `_NormalMap` (the ore's baked nugget normals) or an in-shader **procedural pattern** for generic sprites (Dome/Bevel/Ripples/Radial/Facets; see `Core/context.md` → `SpecularController`) — output bright enough to **bloom** (the scene's global Bloom is what sells the glint). The specular is driven **entirely on the GPU from the REAL lights**: the pass loops over a small set of **global** light uniforms (`_SpecLightCount`, `_SpecLightA/B[MAX_SPEC_LIGHTS]`, cap 4) and, per fragment, computes distance falloff × a **cone gate** × Blinn-Phong against each light's actual world direction. So the hotspot tracks the torch with zero lag and **zero per-sprite CPU** — no script rewrites the light direction anymore. The globals live *outside* `UnityPerMaterial`, so the SRP Batcher is unaffected. Per-instance/material tunables (MPB or material): `_SpecColor` (HDR), `_SpecPower` (tightness), `_SpecIntensity` (resting glint, usually 0), `_LightResponse` (how strongly this sprite answers the lights), `_SpecBoost` (transient flare), `_ShimmerAmp/Speed/Phase` (in-shader idle wobble), and `_SpecLightDir` (direction for the *resting/shimmer/boost* glint only — the light-driven glint ignores it). Keep `_Color` white so `SpriteRenderer.color` still tints. (All 3 passes share one `UnityPerMaterial` CBUFFER layout — required by the SRP Batcher.)
- **Per-instance control & reactivity** — split by cost so idle ore is free. The generic system lives in `Scripts/Core/` (reusable for any shiny sprite: `SpecularLight2D`/`SpecularLight2DManager` emitters + the `SpecularController` receiver base); only the mining glow is ore-specific:
  - `OreSpecularController` (World) **extends the generic `SpecularController`** (Core), inheriting the whole baseline + light-response + idle-shimmer + `Pulse` machinery, and adds only the ore bit: `SetMiningGlow(0..1)` (driven by `MiningResource` while the laser mines), layered onto `_SpecBoost` via the base's `ComposeBoost()`/`IsIdle()` hooks. The base writes the **per-instance baseline ONCE** at spawn via a `MaterialPropertyBlock` (colour/power/resting intensity, `illuminationResponse`→`_LightResponse`, shimmer params) then **disables itself** (no `Update`); the GPU adds the light-driven glint on top. The only per-frame work is transient flares (mining glow / `Pulse`), which wake the component and sleep it again once spent. Net: a field of hundreds of rocks runs **no** per-frame scripts; only the 1–2 rocks currently mined/flashing tick. (For non-ore shiny sprites, use the plain `SpecularController` directly.)
  - `SpecularLight2D` (Core; on each sub `Light2D`, e.g. the turret spotlight) marks that light as a glint driver. `SpecularLight2DManager` (Core; auto-created singleton, no scene object needed) collects every active `SpecularLight2D` and packs them into the global uniforms once per frame in `LateUpdate`. This replaces the old `SubLightOreIlluminator` (deleted) — no more per-tick `OverlapCircle`, no per-sprite illumination push/fade. **Local-multiplayer ready**: up to `MAX_SPEC_LIGHTS` (4) torches glint the same sprite, contributions summed. The cone/beam gate is taken **directly from the `Light2D`'s own inner/outer angles** (packed as cosines; the shader guards the degenerate hard-cone case where inner==outer), so the glint is confined to the visible beam by construction — no separate angle to hand-match (`coneScale` nudges it only if the URP numeric angle differs from what you see). The beam axis is the light's local **+Y** (how URP orients a 2D spotlight).
  - Trade-off vs the old CPU driver: illumination is now **instant** (per-frame GPU) rather than eased over time (`illumFadeSpeed` is gone) — the cone soft-edge + distance falloff smooth it spatially instead. The `onBecameLit` UnityEvent and `SetIllumination` are gone (the controller no longer tracks illumination); reintroduce an opt-in check if a "became lit" hook is needed.
- **Lighting gotchas (important):** (1) a `Light2D` only applies normal maps when its **`NormalMapQuality` ≠ Disabled** — the submarine's turret spotlight must have it enabled (Accurate) or the 3D shine won't show. (2) Light **blend style 0 is Multiply**, so the *diffuse* light only brings a sprite *up to* its albedo — a very dark tint renders near-black and hides relief (the specular pass is what adds brightness beyond albedo). (3) Normal-map relief needs **grazing** light: a large `Light2D.NormalMapDistance` puts the virtual light nearly head-on and flattens the shading — smaller values (~1–3) give more contrast.
