# World Systems

Procedural world generation and the world entities the submarine interacts with (rocks, mining resources, O2 bubbles, enemies). World objects never hold a submarine reference — they resolve the sub from context (`Submarine.FindNearest`, `GetComponentInParent<Submarine>`, or a reference injected at spawn). See `../Submarine/context.md` for the facade these objects target.

## Generation

Spawning is **data-driven**: WHAT spawns lives in `SpawnProfile`/`SpawnRule` assets, not in code. `ChunkSpawner` owns the grid/camera/persistence; `WorldChunk` is a generic executor. See `Spawning/` for the rule types.

- **ChunkSpawner** — generates the world as a persistent grid of chunks around the camera. Pre-spawns every cell within `spawnRadius` (e.g. a 7×7 ring) and **never despawns** them. Maps grid coords → world space with `FloorToInt` (correct for negative Y), filters out cells above the surface (Y ≥ 0), and instantiates one `WorldChunk` per cell, handing it the assigned `SpawnProfile` and a **deterministic per-cell seed** (`SeedMode` = coord-hash, optionally mixed with `worldSeed`). Keyed dictionary keeps chunks unique. Depends on `Camera.main`. A scene gizmo draws each rule's active depth band.
- **WorldChunk** — `Initialize(topY, height, halfWidth, worldX, depth, profile, seed)` builds a seeded `System.Random` + a `SpawnContext` and runs every rule in `profile.AllRules` against the chunk's depth. Holds no rock/enemy/resource knowledge. Fires `onChunkGenerated` (UnityEvent). Spawned entities are parented under the chunk and resolve their own sub deps from context.
- **WorldBoundary** — attach to the camera. Creates invisible left/right `BoxCollider2D` walls parented to the camera so they scroll with the viewport. `halfWidth` must match `ChunkSpawner`'s cell half-width so the walls align with the generated world edges; `wallHeight` covers the view plus buffer.

## Spawning (data model — `Spawning/`)

- **SpawnProfile** (SO) — the rule set a level uses; referenced by `ChunkSpawner`. Aggregates reusable `SpawnRule` assets (`sharedRules`) **and** inline one-off rules (`inlineRules`) via `AllRules`. Has a `globalDensityMultiplier`, validation warnings, and editor buttons: **Test Spawn Chunk** (throwaway in-editor chunk at a depth) and **Generate Default Rules** (scaffolds the 7 legacy-parity rules via `SpawnProfileDefaults`).
- **SpawnRule** (SO) — thin reusable wrapper around one `SpawnRuleData`.
- **SpawnRuleData** — one spawnable: `prefab`, `DepthRange` (min + optional max), `prevalenceByDepth` curve, `CountModel`, `maxPerChunk`, `minSpacing`, `[SerializeReference] PlacementStrategy`, optional `[SerializeReference] InstanceConfigurator`, `zoneTag` + `developerNotes` (per-segment dev notes). `Execute(in ctx, rng, density, parent)` does depth-gate → count → place (spacing retries) → instantiate → scale/configure.
- **PlacementStrategy** (`[SerializeReference]`) — `ScatterPlacement` (width band + insets), `WallProtrusionPlacement` (flush-edge rocks; returns a `scaleOverride` = protrusion×height), `CenterBandPlacement` (tighter central band). Returns a `PlacementResult { position, scaleOverride? }`.
- **CountModel** — `SingleRoll` (probability), `Range` (flat min–max), `CurveRange` (ramps with depth). Optional `CountSplit` (Floor/Ceil half) lets two rules share one rounded budget — used to reproduce the original wall/center rock split exactly.
- **InstanceConfigurator** (`[SerializeReference]`) — post-spawn setup. `DepthSizeConfigurator` (depth-driven O2 `SetSize`), `DepthScaleConfigurator` (depth-driven rock localScale).
- **SizeSampler** — shared roll→curve→lerp helper, reused by `O2DropConfig` and `DepthSizeConfigurator`. **SpawnRng** — `System.Random` float/bool extensions for deterministic sampling.
- Generation is reproducible: same `worldSeed` + cell → identical chunk. `LevelConfig`'s zone spawn budgets (`ZoneConfig`) are **deprecated** by this system; its world shape, `ZoneType`, and `ExitGateWorldY` remain live (`ZoneType` is an optional inspector tag on rules, not a gate).

## Entities

- **EnemyController** — sea-creature AI: Patrol → Chase → WindUp → Attacking → AttackCooldown (+ terminal Dead) state machine. Acquires the player via `Submarine.FindNearest(transform.position)` in Start and caches its `Health`. Detection uses `detectionRadius`/`deaggroRadius` hysteresis; the attack telegraphs (orange tint + DOTween `DOPunchScale` on an intent indicator) then lunges (red, `lungeSpeed`), dealing `attackDamage` to the player's `Health` on contact (guarded to once per lunge). Subscribes to its own `Health.onDeath` to drop `o2BubblePrefab` ×`bubbleDropCount`. Composes with `HitFlash` (which preserves these state tints). Force-free Rigidbody2D driven by `linearVelocity`.
- **MiningResource** — laser-mineable node (on the "Resource" layer, trigger `CircleCollider2D`). `SetMiningProgress(0..1)` is called by `MiningLaser` each frame the beam holds it, lerping the sprite toward white. `Collect(Submarine sub, airMultiplier = 1)` — called by the laser at completion (separated so magnet/auto upgrades can also call it) — awards `sub.Resources.AddResources(...)` and rolls `scrapDropChance` for `sub.Scrap.AddScrap()`.
- **O2Pickup** — air bubble (enemy drop or passive scatter; trigger `CircleCollider2D`). `Collect(Submarine sub, airMultiplier = 1)` restores `sub.O2.RestoreCapacity(...)` and `sub.O2.AddAir(replenish × multiplier)`, fires `onCollected`, then self-destructs. `collectOnContact` is **off by default** — collection normally goes through `O2PickupPump`'s sweet-spot mechanic (which calls `Collect` with a graded multiplier); when on, `OnTriggerEnter2D` resolves the sub via `other.GetComponentInParent<Submarine>()`.
- **RockObstacle** — breakable rock (Collision layer). Broken by the `MiningLaser` (hold-beam timer → `Break()`) or by a fast enough collision on `breakFromLayers`. Built as a **composite of child "nugget" `SpriteRenderer`s** (the foundation for future per-chunk mining/detach). `SetProgress`/`ResetProgress` tint **every** child toward `damagedColor` ("heating up") and back, caching each renderer's original color in `Awake` via `GetComponentsInChildren`.

## Rock / ore visuals

The minable rock reads as a clustered, lit ore patch (Delta-V / Factorio style).

- **Procedural art** — `OreNuggetGenerator` (`World/Editor/`, menu **Tools/Custom/Generate Ore Nuggets**) bakes N grayscale nugget sprites + matching normal maps into `Assets/Submachina/Art/Ore/` (`Nugget_*_albedo.png` / `_normal.png`). Reproducible from `seed`; layered Perlin + Worley noise for surface/cracks, a hemispherical dome bias in the normal for rounded relief, rim AO, and sparse mineral specks.
- **Per-sprite normals** — each normal is attached as the albedo sprite's `_NormalMap` **Secondary Texture**, so all nuggets share the one default `Sprite-Lit-Default` material (no per-nugget material instances). Normals are imported as **Default, sRGB off, uncompressed** because the URP 2D sprite normals pass reads straight RGB (`UnpackNormalRGBNoScale`) — *not* Unity's NormalMap type.
- **Grayscale + tint** — textures are neutral grey so `RockObstacle`'s `SpriteRenderer.color` tint drives the look (and the heat lerp), and one texture set can serve copper/scrap via different tints.
- **Shadows** — each nugget carries a silhouette `ShadowCaster2D` (cloned from the prefab's original). At scale (hundreds of rocks) this multiplies casters and the 2D renderer is capped at 1 shadow texture — if shadows get heavy, keep casters only on the 1–2 largest nuggets.
- **Metallic shine** — URP 2D lighting is diffuse-only (no specular), so the nuggets use a custom material `Materials/OreLit.mat` (shader `Shaders/OreLitSpecular.shader`, `Submachina/2D/OreLitSpecular`). It's a verbatim copy of URP's Sprite-Lit-Default with one addition in the Universal2D pass: a Blinn-Phong **HDR specular** computed from the sprite's `_NormalMap` against a *virtual* key light, output bright enough to **bloom** (the scene's global Bloom is what sells the glint). Tunable on the material: `_SpecColor` (HDR), `_SpecPower` (tightness), `_SpecIntensity`, `_SpecLightDir`. Keep `_Color` white so `SpriteRenderer.color` still tints. Caveat: the glint uses a fixed `_SpecLightDir`, so it doesn't track the sub's actual torch — set it to roughly the typical light angle. (All 3 passes share one `UnityPerMaterial` CBUFFER layout — required by the SRP Batcher.)
- **Per-instance control & reactivity** — `OreSpecularController` (on the rock root) drives the OreLit specular per-instance via a **`MaterialPropertyBlock`** — no material copies, no global edits, batching-friendly. It is the *single writer* of the block and composes every contribution so they never fight: `intensity = base*(1+idleMod) + illumination*response + pulse`. Use it for (a) per-instance look variation (colour/power/intensity baseline), (b) idle shimmer (`animate` sine/pingpong/perlin), and (c) external drivers via `SetIllumination(value, dirToLight)` and `Pulse(amount)` (e.g. an MMF feedback flashes the glint without overwriting light reactivity). `SubLightOreIlluminator` (on a sub Light2D) is the proximity driver — a throttled `OverlapCircle` on the ore layers pushes distance falloff × a **hard cone gate** + the light direction into nearby controllers (light-pushes-to-ore: cheap for few lights / many ore; out-of-range ore self-fades). When `aimGlintAtLight` is on, the glint direction tracks the actual light, working around the shader's fixed `_SpecLightDir`. The cone is centered on the light's local **+Y** (how URP orients a 2D spotlight via `transform.rotation`, so it tracks the real beam); a Scene-view gizmo draws the arc and a "Copy Angles From Light2D" button seeds the half-angle from `pointLightOuterAngle`. The URP angle→width mapping is unintuitive, so match the gizmo to the visible beam by eye if needed.
- **Lighting gotchas (important):** (1) a `Light2D` only applies normal maps when its **`NormalMapQuality` ≠ Disabled** — the submarine's turret spotlight must have it enabled (Accurate) or the 3D shine won't show. (2) Light **blend style 0 is Multiply**, so the *diffuse* light only brings a sprite *up to* its albedo — a very dark tint renders near-black and hides relief (the specular pass is what adds brightness beyond albedo). (3) Normal-map relief needs **grazing** light: a large `Light2D.NormalMapDistance` puts the virtual light nearly head-on and flattens the shading — smaller values (~1–3) give more contrast.
