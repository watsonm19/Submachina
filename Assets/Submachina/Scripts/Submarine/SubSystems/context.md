# Submarine Subsystems (SubmarineComponents)

These are the modular subsystems that make up a submarine. Each extends **SubmarineComponent** and is reached from siblings via the facade (`Sub.O2`, `Sub.Physics`, etc.). Most ship as prefabs under `Prefabs/SubSystems`, slotted into a `SubmarineConfig` and assembled by `Submarine.Build()`. See `../context.md` for the facade and feedback overview.

## Base classes

- **SubmarineComponent** — abstract base for all submarine subsystems. `Awake()` does `GetComponentInParent<Submarine>()` then `Sub.Register(this)`; `OnDestroy()` unregisters. Derived classes call `base.Awake()` first. This auto-registration enables **runtime swapping** (destroy old, instantiate new — the registry stays current). An editor-only banner reads the component's `[UsesFeedbacks]` attribute and renders the feedback keys as chips. Also provides `ResolveAction(InputActionReference)` and `HasMouseInput` for the per-player input system.

- **InputSubmarineComponent** — intermediate base for any subsystem that reads player input (extends `SubmarineComponent`). Eliminates the per-component boilerplate of declaring/resolving/enabling/disabling actions. Subclasses call `RegisterAction(ref)` in Awake; the base handles enable/disable lifecycle in `virtual OnEnable`/`OnDisable`, and `PrimaryAction` exposes the first (usually only) registered action. Supports N actions per component and runtime rebinding via `RebindActions()` (called by `SubmarineInputModule.Reassign`). A green "Input" sub-banner renders action names as chips in the inspector.

- **SweetSpotPump** — abstract base for sweet-spot timing pumps (`extends InputSubmarineComponent, ISweetSpotPump`). Owns router registration in `sealed override OnEnable/OnDisable` (chains base action lifecycle + `Sub.Pumps.Register/Unregister` + `OnPumpEnabled`/`OnPumpDisabled` hooks). The sealed methods prevent derived pumps from accidentally losing registration; pump-specific work goes in the hooks. New pumps get correct action lifecycle and registration for free.

## Routers (arbitration & decoupling)

- **SubmarineFeedbackRouter** (`Sub.Feedbacks`) — semantic feedback switchboard. Serialized `mappings` pair each `FeedbackId` key with one or more `MMF_Player`s; `Play(key, position, intensity)` does an O(1) lookup and plays all mapped players, `Stop(key)` halts looping ones. Every gameplay system routes juice through this instead of holding `MMF_Player` references. Editor button `AddMissingMappings()` auto-populates via reflection over `SubFeedbacks` fields. A custom Odin `FeedbackIdDrawer` shows a categorized dropdown for each key. **Pub/sub:** `Play`/`Stop` also raise the C# events `FeedbackPlayed(key, position, intensity)` / `FeedbackStopped(key)` — fired even when a key has *no* MMF mapping, so a key can drive pure listeners (see `FeedbackEventListener`) with no player attached.
- **SubmarinePumpRouter** (`Sub.Pumps`) — arbitration for the shared pump input. Pumps self-`Register`/`Unregister` via the `SweetSpotPump` base (OnEnable + a Start fallback for the Awake-order race; Unregister on OnDisable). `Active` returns the registered `ISweetSpotPump` with the highest `ControlPriority` whose `WantsControl` is true (first-registered breaks ties); `IsActive(pump)` is the per-pump check. No hand-wired references between pumps or bars.
- **SubmarineAnchorRouter** (`Sub.Anchors`) — semantic mount-point registry (the visual-location mirror of the feedback router). Maps each `AnchorId` key to the `Transform` of a `SubmarineAnchor` marker. `Get(key)` returns the transform (falling back to the sub root on a miss); `TryGet(key, out t)` skips the fallback. Markers self-`Register`/`Unregister`, and `Awake` back-fills any anchors already nested under the sub. See `../SubAnchors/context.md` for the key types.

## Anchors & feedback binding (decoupled VFX placement)

- **SubmarineAnchor** — a marker placed on a child transform (muzzle, nose, tail) holding an `AnchorId` key; self-registers with `Sub.Anchors` (OnEnable/OnDisable) and draws a Scene gizmo. `Key` and `Point` expose the key and its transform.
- **FeedbackAnchorBinder** — plain MonoBehaviour on a self-contained feedback prefab. On `Start` it resolves its `AnchorId` via `GetComponentInParent<Submarine>().Anchors` and re-points the player's `MMF_ParticlesInstantiation`: `Attach` parents + nests the particles so they follow the sub; `PositionOnly` spawns a one-shot at the anchor. Swapping the prefab or its key moves the effect without touching gameplay code (Mode A). Modules can instead pass `Sub.Anchors.Get(key).position` to `Sub.Feedbacks.Play` for dynamic points (Mode B).
- **AnchorMount** — generic counterpart to `FeedbackAnchorBinder`. Plain MonoBehaviour that, on `Start`, re-parents *its own GameObject* onto an `AnchorId` (via `Sub.Anchors.TryGet`). `snapToAnchor` drives local position from the anchor origin plus `localOffset` (optionally `matchRotation`); off = keep world position and only re-parent. Object-agnostic — works for a light, sprite, trail, child rig — so a self-contained prefab can position itself at a named mount point with no hard reference into the sub hierarchy.

## Generic feedback reactions (pub/sub)

- **FeedbackEventListener** — `SubmarineComponent` that subscribes to `Sub.Feedbacks.FeedbackPlayed`/`FeedbackStopped` and re-fires UnityEvents when the broadcast key matches its serialized `key`. `onPlayed`/`onStopped` are parameterless (simple reactions); `onPlayedAtPosition` (`UnityEvent<Vector3>`) and `onPlayedWithIntensity` (`UnityEvent<float>`) pass the play args through for dynamic binding. This turns the one-way router into a bus any object can react to without gameplay code referencing it — e.g. a self-contained dash light prefab carrying `AnchorMount` (positions itself) + two listeners (`DashStart`→off, `DashReady`→on).

## Core movement & aim

- **O2System** (`Sub.O2`) — authoritative air tank and single source of truth for air state: `CurrentAirPressure`, `MaxAir`/`OriginalMaxAir`, and `ActiveDecayRate` = `(baseDecayRate × exertionMult + miningExtra) × depthMultiplier`. Exertion flags `IsThrusting` (set by physics) and `IsMining` (set by the laser) raise drain; capacity decays over time floored at `minMaxCapacity`; air at zero bleeds `Health`. API: `AddAir`, `ConsumeAir`, `RestoreCapacity`, `RefillAir`; events `onO2Depleted`/`onO2Restored`. Writes the `currentO2`, `maxAirCapacity`, `originalMaxAir` atoms for the HUD; reads the optional `currentDepth` atom for depth scaling.
- **SubmarinePhysicsController** (`Sub.Physics`) — force-based (not velocity-set) Rigidbody2D controller. Reads `thrustAction`, applies lateral thrust / upward-only counter-thrust, and applies the `currentDescentSpeed` atom (from `CurrentManager`) as downward ocean current each FixedUpdate. Gravity is disabled. Exposes `ThrustInput`, `IsDashing` (set by `CavitationBurst` to bypass the speed clamp), and `FacingSign`; drives sprite facing/tilt in LateUpdate. Writes `Sub.O2.IsThrusting`.
- **TurretAim** (`Sub.Turret`) — dual-input aim. Prioritizes gamepad right-stick (`aimAction`, past `stickDeadzone`) over mouse fallback, with seamless device switching and last-direction hold when idle. Exposes `AimDirection`, read by `MiningLaser`, `PlayerAttack`, and `CavitationBurst`.

## Pump system (sweet-spot air mechanics)

All pumps extend the **SweetSpotPump** base (`InputSubmarineComponent` + `ISweetSpotPump`) and bind the **same** pump InputAction; the `SubmarinePumpRouter.Active` pump owns the input and the shared `BellowsBar`. The interface exposes the read state the router/HUD need: `ChargeProgress`, `IsInSweetSpot`, `SweetSpotMin/Max`, `IsAirLocked`, `IsOnCooldown`, plus `WantsControl` and `ControlPriority` for arbitration. See the base classes section above for `SweetSpotPump`'s lifecycle.

- **ManualBellowsPump** — the always-on baseline (`ControlPriority 0`, `WantsControl = enableManualPumping`). Hold-to-charge with a sweet-spot window; a Perfect/Weak release calls `Sub.O2.AddAir(...)`, overshoot vents for nothing. Anti-spam **Air Lock** after rapid presses, plus a post-Perfect cooldown. `IsActivePump` reads `Sub.Pumps.IsActive(this)` (defaults true if no router exists, so it runs solo); when not active it cancels any in-flight charge so it can't stick. Plays `PumpCharge`/`PumpPerfect`/`PumpWeak`/`AirLock`.
- **O2PickupPump** — contextual intake pump (`ControlPriority 10`, outranks manual). Runs a looping 0→1 charge; pressing while looping grades the collect by timing (sweet spot = full reward, otherwise weak) and routes air via `O2Pickup.Collect(Sub, multiplier)`. `WantsControl` while looping **or** a pickup is in range. With `autoActivateInRange` it starts on range-enter and stops quietly when the last pickup leaves; `requirePickupToStart` gates manual starts. No cooldown. Detects pickups via `Physics2D.OverlapCircleAll`; draws a procedural LineRenderer ring.

**Hand-off:** the intake pump takes over near bubbles and the manual pump resumes the instant it lets go — entirely through the router, no direct references. **Independence:** with only one pump registered, that pump is active whenever it wants control, so a bellows-only or intake-only sub behaves correctly.

**Scene wiring (Proto_Descent):** `O2System`, `SubmarineFeedbackRouter`, `SubmarinePumpRouter`, `ManualBellowsPump`, and `O2PickupPump` live on the submarine root, sharing one pump InputAction. A single `BellowsBar` child follows `Sub.Pumps.Active` — no per-pump bars or manual references.

## Weapons & abilities

- **MiningLaser** — continuous beam fired along `Sub.Turret.AimDirection` (`mineAction` hold). Gated by `Sub.O2.CurrentAirPressure > 0` and sets `Sub.O2.IsMining`. Raycasts on `miningLayer`; calls `MiningResource.SetMiningProgress(...)` each frame and `Collect(Sub)` at completion. Drives `MiningBeamVFX` and plays looping `MiningActive` / one-shot `MiningCollect`.
- **PlayerAttack** — directional melee cone. Gathers enemies in `attackRange` on `enemyLayer` via `OverlapCircleAll`, filters by dot product against `Sub.Turret.AimDirection` (`coneHalfAngle`), and calls each `Health.TakeDamage`. Events `onAttack`/`onDamageDealt`; plays `AttackSwing` at its `attackAnchor` (resolved via `Sub.Anchors`, default `Muzzle`); procedural LineRenderer arc visual.
- **CavitationBurst** — directional dash. Consumes `Sub.O2.ConsumeAir(airCost)` (gated on air), applies an impulse with reduced drag for `burstDuration`, and sets `IsDashing` so physics lets it exceed `maxSpeed`. Direction priority: thrust input → velocity → `Sub.Turret.AimDirection`. Events `onBurstStart`/`onBurstEnd`/`onBurstReady`; plays `DashStart` (launch) / `DashEnd` (slide ends) / `DashReady` (cooldown finished — fired from `Update` once `burstCooldown` elapses, the true "ready again" moment, distinct from the earlier `DashEnd`).

## Hull, cargo & ballast (depth-progression systems)

- **HullSystem** (`Sub.Hull`) — unified hull strength + depth pressure model. **Rated depth is FIXED by loadout** (`RatedDepth = Strength × safety / (pressurePerMeter × PressureLoadMult)`, shared static `ComputeRatedDepth` also used by `HubStats`) — damage never lowers it, so ascending above it always stops pressure damage. Past rated depth a **strain timer** accrues and Health bleeds at `excess × cascadeDamageRate × strainRampCurve(strainTime)` — a designer `AnimationCurve` makes the first seconds a cheap dip and loitering lethal; strain recovers (faster, `strainRecoveryRate`) once back above. Impact absorption still softens with damage but is floored: `HullResistance = Strength × lerp(integrityFloor, 1, Integrity)` (no death spiral). `EvaluateImpact(speed)` converts a collision into overload damage only when `PressureLoad + ImpactLoad` exceeds resistance; `EvaluateAttack(baseDamage)` scales **enemy** hits ×1 (surface) → ×`maxAttackVulnerability` (rated depth), by depth only — `RammingEnemy`/`EnemyController` route through it. **Pump-to-hull**: `PumpAirIntoHull(o2)` (the pump's Hull destination, sweet-spot only) converts air to `PressureBoost` counter-pressure (extends live `RatedDepth` until it vents at `boostDecayPerSecond`) at a `pressurizeSelfDamage` HP cost (default 25). Warning creaks fire through descending reserve bands. Stats: `HullStrength`, `PressureLoadMult`, `ImpactLoadMult` (category 9). Feedbacks: `HullCreak`/`HullOverload`/`CrushZone`/`PressureDamage`/`HullPressurize` (category 9). `CollisionDamage` routes through it when present, legacy flat damage otherwise. HUD: `HullReserveBar`, `DepthGauge` ("142m / 160m"), `PressureStrainBar`, `VulnerabilityGauge` ("DMG ×1.5 · SAFE <6.2m/s" — live `AttackDamageMult` / `SafeImpactSpeed`).
- **CargoHold** (`Sub.Cargo`) — typed cargo storage for mined resources (`InputSubmarineComponent`). `Add(ResourceType, units)` clamps to `Capacity` (`SubStats.CargoCapacity`, category 10); partial stores fire `onCargoRejected` so mining feedbacks "hold full" without hard-blocking. Contents contribute mass (units × `ResourceType.unitMass`) via the physics mass aggregation, and are banked to the profile by `MissionController` on extraction (`Meta/context.md`). **Jettison**: holding `dumpAction` (B / dpad-right) releases units heaviest-type-first as re-collectible `CargoPickup` parcels (World) — the anti-stuck escape valve for the ballast interplay (a hold can outweigh a full tank). Parcels sink slowly, tint to their resource, and re-stow on contact after a spawn-grace period. Feedbacks: `CargoAdded`/`CargoFull`/`CargoRejected`/`CargoDumped` (category 10).
- **BallastTank** (`Sub.Ballast`) — thrust-free vertical traversal on a SHARED, conserved O2 economy. `AirFraction` 0..1 is how much of the tank holds air (rest floods); a three-position **gear shifter** (`BallastMode` Empty/Neutral/Full; shift-down C / dpad-down, shift-up X / dpad-up, one step per press) commands a target and the tank eases toward it, exchanging O2 with the main reserve: filling DRAWS from `Sub.O2` (stalls when dry), venting RETURNS air, and overflow past a full main tank spawns real `O2Bubble` pickups at the sub (reclaimable — air is never destroyed). Buoyancy is piecewise-linear through three tuning points: Empty = sink with the current at full speed, Neutral = cancel the `referenceCurrentForce` (hover), Full = 2× reference (rise about as fast as you fall); heavy cargo can outweigh the lift, which then just assists upward thrust. Water mass registers via the physics aggregation. Owns the **PumpDestination** cycle (V / dpad-left): O2 reserve → Ballast → Hull (skipped when no `HullSystem`). Destination Ballast routes pump air into `AddAirToBallast` (lift without draining the reserve; the gear auto-promotes to hold the level; overflow banks to the main tank); destination Hull routes into `HullSystem.PumpAirIntoHull` (pressure headroom at an HP cost). **Sweet-spot gate**: only a sweet-spot pump/collect earns Ballast or Hull routing — weak pumps always dribble into the O2 reserve (`CollectGrade` on `O2Pickup.Collect`; contact grabs keep legacy ballast routing but never touch the hull). Subs without the tank behave exactly as before (pumps null-check). Stats category 11; feedbacks category 11 (`BallastShift` is the gear click). A loadout choice via the `BallastTankFeature` toggle upgrade.
- **Mass aggregation** — `SubmarinePhysicsController.RegisterMass(source, kg)` / `UnregisterMass`: contributors (cargo, ballast water, hauled mission pods) push mass in; `rb.mass = baseMass + Σ`, so a loaded sub accelerates slower under the same thrust. `BaseMass`/`TotalMass` exposed.

## Economy

- **ScrapManager** (`Sub.Scrap`) — consumable scrap bank (earned from mining, spent to heal). `AddScrap()` (capped at `maxScrap`) from `MiningResource`; `useScrapAction` heals `Sub.Health` by `healPerScrap` when banked and below full. Events `onScrapAdded`/`onScrapFull`/`onScrapUsed`/`onNoScrap`/`onFullHealth`; plays the matching Scrap feedbacks. Read by `ScrapDisplay`.
- **ResourceManager** (`Sub.Resources`) — roguelite progression. `AddResources(amount)` (from `MiningResource`) accumulates toward `threshold = baseThreshold + level × thresholdIncrement`, carrying overflow and firing multiple level-ups per call. Events `onResourcesAdded`/`onLevelUp` (the latter drives the upgrade-draft UI). Writes the `currentResources` / `resourceThreshold` atoms for `ResourceBar`; plays `ResourcesAdded`/`LevelUp`.

## Sensing

- **SonarSystem** (`Sub.Sonar`) — emit-and-return sonar. A manual, cooldown-gated `pingAction` press emits a pulse; detection reuses the `OverlapCircleAll` idiom to find `SonarTarget`s in range (filtered per-target by `range × SizeDetectFactor(sizeClass) × reflectionStrength` — the size→detect-range mapping is the sonar's own "Detection by Size" config, five per-size-class sliders, 0 = that size class is undetectable), then schedules each return for `2 × distance / pingSpeed` seconds out — so **closer contacts ping back sooner** (the distance cue; a literal expanding-wavefront sim can replace the scheduler later without touching the public API). Produces fully-populated `SonarContact`s (target, position, direction, distance, signature, delay) exposed via `ActiveContacts` and the C# events `PingEmitted` / `ContactScheduled` (fired at ping time with the full contact incl. `ReturnDelay`, so presentation can act during the echo's flight) / `ContactReturned` / `PingResolved` (plus inspector `onPingEmitted` / `onContactReturned`). Stats `SonarRange` / `SonarCooldown` / `SonarPingSpeed` (category 8) tune it through the upgrade table. Plays `SonarPingEmit` on emit and `SonarReturn` (or the signature's own cue) per return with **intensity ∝ proximity**.

- **SonarReturnRipples** — diegetic sonar-return VFX (sibling of `SonarSystem` on the sonar prefab). Subscribes to `ContactScheduled` and turns each echo into a real expanding water ripple via `DistortionRippleBus`, emitted **at the contact's world position** — on-screen contacts ripple in place, off-screen ones sweep into frame as a natural arc from their direction. Default `EchoWavefront` sync launches the ripple at the physical reflection moment (half the round trip) with per-ripple expansion speed matched to `ResolvedPingSpeed`, so the wavefront reaches the sub exactly when `SonarReturnAudio` beeps (`OnReturn` mode instead starts the ripple at the beep). Proximity maps to the whole wave character (arrival strength w/ contrast curve, spatial frequency, phase speed, ring band width, pulse-train count/decay) — far contacts read as one faint thin ring, the spot-the-direction mini-game. Fade-compensates emitted strength against the controller's lifetime envelope, caps ripples per ping (shared 16-slot pool), and gates by `minimumTier` (default Direction, since a ripple leaks bearing). A second single gate, `voiceTier` (default Identify), unlocks every identity trait at once: the signature's **Ripple Voice** (tint glow in `blipColor`, chromatic glint, pulse rhythm, frequency/phase/width character — authored on `SonarSignature`) plus `sizeStrengthInfluence` biasing strength by size class; below it every echo ripples generically (the distance mapping is never gated). Coexists with `SonarHud` for now; may replace it. Odin test buttons fake near/far contacts and can impersonate a `debugSignature` to audition voices.

- **SonarReturnAudio** — self-contained sonar sound (sibling of `SonarSystem` on the sonar prefab). Subscribes to `SonarSystem.PingEmitted` / `ContactReturned` and plays a beep via a local `AudioSource` (volume + pitch scaled by proximity on returns). The project's documented MMF fallback: a sub makes sound with no feedback-router / MMSoundManager wiring, while the `SonarPingEmit` / `SonarReturn` keys still fire so richer MMF juice can be layered on later. The system is tier-agnostic — it always yields full contacts and exposes `CurrentTier`; the HUD/audio down-sample by tier. `CurrentTier` resolves to the highest active tier feature via `Sub.Upgrades.IsFeatureActive(...)` (falling back to `fallbackTier` when no `UpgradeManager` is present, so the prefab is testable in isolation). Odin "Fire Test Ping" + a force-tier override + range/contact gizmos aid tuning. See `../../World/Sonar/context.md` for the detectable-object side and `../Upgrades/context.md` for the tier-unlock upgrades.
